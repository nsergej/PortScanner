# Security Policy

## Supported Version

Security updates are applied to the latest version available from the `main` branch. Older builds may no longer receive fixes.

## Report a Security Issue Privately

Do not open a public issue, discussion, or pull request containing security-sensitive details.

Use GitHub's private vulnerability reporting feature:

1. Open the repository's [Security Advisories page](https://github.com/nsergej/PortScanner/security/advisories/new).
2. Select **Report a vulnerability**.
3. Include the affected version, a clear description, reproduction steps, potential impact, and any suggested mitigation.
4. Wait for the maintainer to respond before publishing technical details.

If private vulnerability reporting is unavailable, contact the repository owner through a private contact method listed on the owner's GitHub profile. In that case, send only a brief request for a secure reporting channel until a private conversation is established.

## Responsible Testing

- Test only systems and networks that you own or are explicitly authorized to test.
- Use the minimum activity necessary to demonstrate the issue.
- Do not access, retain, modify, or disclose third-party data.
- Allow the maintainer reasonable time to investigate and prepare a fix before public disclosure.

## Non-Security Bugs

Ordinary functional or documentation bugs that do not expose sensitive information may be reported through a public GitHub issue.
